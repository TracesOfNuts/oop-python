# 03 - Making Decisions

**What you will learn**

- How to compare values, and get `True` or `False`.
- How to make your code choose what to do with `if`, `elif` and `else`.
- How to combine conditions with `and`, `or` and `not`.

All of these are `if` statements.

## 1. Comparing values

A **comparison** asks a yes or no question.
The answer is always `True` or `False` (a `bool`).

| Symbol | Question | Example | Result |
| --- | --- | --- | --- |
| `==` | is equal to? | `5 == 5` | `True` |
| `!=` | is not equal to? | `5 != 5` | `False` |
| `<` | is less than? | `3 < 5` | `True` |
| `>` | is greater than? | `3 > 5` | `False` |
| `<=` | is less than or equal to? | `5 <= 5` | `True` |
| `>=` | is greater than or equal to? | `4 >= 5` | `False` |

@@ code
age = 19
print(age >= 18)
print(age == 21)
print("Amy" == "Amy")

@@ md
⚠️ **`=` and `==` are different.**

- `=` **puts** a value into a variable: `age = 19`.
- `==` **asks** whether two values are equal: `age == 19`.

@@ predict True or False?
@@ run
print(10 > 3)
print(2 == 3)
print(7 != 8)
print("tea" == "Tea")
@@ output
True
False
True
False
@@ explain
`10 > 3` and `7 != 8` are true.
`2 == 3` is false.
`"tea" == "Tea"` is **false**, because Python treats small `t` and capital `T` as different letters.
Remember this one. It comes back later.

@@ predict = versus ==
@@ run
x = 5
print(x == 5)
x == 7
print(x)
@@ output
True
5
@@ explain
`x == 7` only **asks** a question (is x equal to 7?).
It does not change `x`.
The answer `False` is thrown away, and `x` is still `5`.

## 2. `if`: do something only when a condition is true

```python
if condition:
    lines that run only when the condition is True
```

The rules are the same as for `def`:

- A colon `:` at the end of the `if` line.
- The lines that belong to the `if` are **indented** by 4 spaces.

@@ code
balance = 20
price = 4.5

if balance >= price:
    print("Payment OK")
    balance -= price

print("Balance is now", balance)

@@ md
Try changing `balance` to `3` and run the cell again.
The two indented lines are skipped, but the last line always runs, because it is not indented.

@@ predict Indented or not?
@@ run

if temperature > 30:
    print("It is hot")
    print("Drink water")
print("Have a nice day")
@@ output
Have a nice day
@@ explain
`25 > 30` is `False`, so both indented lines are skipped.
The last line is not indented, so it is not part of the `if`. It always runs.

## 3. `else`: do something different when it is false

`else` gives a second path.
Exactly **one** of the two blocks runs.

@@ code
def ticketType(age):
    if age < 12:
        return "Child"
    else:
        return "Adult"

print(ticketType(8))
print(ticketType(30))

@@ md
💡 Notice the indentation inside a function.
The `if` is indented once (it is inside the function).
The `return` lines are indented twice (they are inside the `if`).

## 4. `elif`: more than two choices

`elif` means "else, if".
Python checks the conditions **from top to bottom**.
It runs the block of the **first** condition that is true, and skips all the rest.
`else` at the end catches everything that did not match.

@@ code
def drinkSize(ml):
    if ml >= 700:
        return "Large"
    elif ml >= 500:
        return "Medium"
    else:
        return "Small"

print(drinkSize(750))
print(drinkSize(500))
print(drinkSize(300))

@@ predict First match wins
@@ run
mark = 85
if mark >= 50:
    print("Pass")
elif mark >= 80:
    print("Distinction")
else:
    print("Fail")
@@ output
Pass
@@ explain
`85 >= 50` is true, so Python prints `Pass` and skips the rest.
It never even looks at `mark >= 80`.
The order is wrong: the most demanding check (`>= 80`) should come first.

## 5. `and`, `or`, `not`

You can join conditions:

| Word | Meaning | Example |
| --- | --- | --- |
| `and` | both must be true | `age >= 18 and isMember` |
| `or` | at least one must be true | `day == "Sat" or day == "Sun"` |
| `not` | flips True and False | `not isFull` |

You can also write a range check in one go: `0 <= mark <= 100`.

@@ predict and / or / not
@@ run
age = 20
isMember = False
print(age >= 18 and isMember)
print(age >= 18 or isMember)
print(not isMember)
print(0 <= age <= 100)
@@ output
False
True
True
True
@@ explain
`and` needs **both** sides true, but `isMember` is `False`, so the result is `False`.
`or` needs only **one** side true, and `age >= 18` is true.
`not False` is `True`.
`0 <= 20 <= 100` checks that 20 is between 0 and 100, which is true.

## 6. Tools for checking text

Strings have built-in **methods**.
A method is a function that belongs to a value.
You call it with a dot: `text.lower()`.

| Tool | What it does | Example | Result |
| --- | --- | --- | --- |
| `text.lower()` | all small letters | `"Tea".lower()` | `"tea"` |
| `text.upper()` | all capital letters | `"Tea".upper()` | `"TEA"` |
| `text.strip()` | removes spaces at both ends | `"  hi  ".strip()` | `"hi"` |
| `len(text)` | number of characters | `len("hello")` | `5` |
| `part in text` | is `part` inside `text`? | `"ea" in "Tea"` | `True` |
| `text.startswith(part)` | does `text` begin with `part`? | `"91234567".startswith("9")` | `True` |
| `text.isdigit()` | is every character a digit 0 to 9? | `"123".isdigit()` | `True` |

⚠️ These methods do **not** change the original text.
They give back a new value, so you must use or store the result.

@@ predict Text tools
@@ run
name = "  Amy Tan  "
print(name.strip())
print(name.strip().upper())
print(len(name))
print(len(name.strip()))
@@ output
Amy Tan
AMY TAN
11
7
@@ explain
`strip()` removes the spaces at both ends, giving `Amy Tan`.
Then `.upper()` makes it all capitals.
The original has 2 spaces in front and 2 at the end, so its length is 11. After stripping it is 7.

@@ predict in, startswith, isdigit
@@ run
phone = "91234567"
print("123" in phone)
print(phone.startswith("8"))
print(phone.isdigit())
print("12a4".isdigit())
print("".isdigit())
@@ output
True
False
True
False
False
@@ explain
`"123"` appears inside `"91234567"`.
The phone starts with `9`, not `8`.
All characters of `"91234567"` are digits, so `isdigit()` is `True`.
`"12a4"` has a letter, so it is `False`.
An empty string has no digits at all, so `isdigit()` is also `False`.

## 7. Comparing text without caring about capitals

🎯 Exam questions often say "search by name, **case insensitive**".
That means `"amy"`, `"Amy"` and `"AMY"` must all count as the same name.
The trick: make **both** sides lowercase before you compare.

@@ code
storedName = "Amy"
typedName = "AMY"
print(storedName == typedName)                  # False
print(storedName.lower() == typedName.lower())  # True

@@ predict Brackets with and / or
Python does all the `and` parts before the `or` parts, like `*` before `+` in maths.
@@ run
phone = "1234567"
print(len(phone) == 8 and phone.startswith("6") or phone.startswith("1"))
print(len(phone) == 8 and (phone.startswith("6") or phone.startswith("1")))
@@ output
True
False
@@ explain
The first line is read as `(len(phone) == 8 and phone.startswith("6")) or phone.startswith("1")`.
The left part is `False`, but the right part is `True`, so the answer is `True`, even though the phone has only 7 digits.
The second line uses brackets so that the length must be 8 **and** one of the starts must match. That gives `False`, which is what we want.
💡 When you mix `and` and `or`, always use brackets.

## 9. "Will this addition go over the maximum?"

🎯 Exam questions often say:
"Raise an exception if **this addition results in more than** the maximum number of items."

Read it carefully.
You have to imagine the list **after** adding one more.
If you already have `currentCount` items, after adding there will be `currentCount + 1`.
So the check is `currentCount + 1 > maxCount`.

@@ predict Full or not?
@@ run
maxCount = 3
currentCount = 2
print(currentCount + 1 > maxCount)
currentCount = 3
print(currentCount + 1 > maxCount)
@@ output
False
True
@@ explain
With 2 items, adding one more gives 3, which is not more than 3. So it is allowed (`False` means "not too many").
With 3 items, adding one more gives 4, which is more than 3. So it is too many (`True`).

def memberPrice(price, tier):
    tier = tier.lower()
    if tier == "gold":
        return price * 0.8
    elif tier == "silver":
        return price * 0.9
    else:
        return price

print(memberPrice(100, "Gold"))

@@ solution
def checkAmountText(text):
    text = text.strip()
    if text == "":
        return "Please enter a value"
    elif not text.isdigit():
        return "Value must be numeric"
    elif int(text) <= 0:
        return "Value must be positive"
    else:
        return f"Amount: ${int(text):.2f}"

print(checkAmountText(" 25 "))

@@ write Why does the order of checks matter?
In `checkAmountText`, why must the "empty" check come **before** the "positive" check?
What would go wrong if you did `int(text) <= 0` first?
@@ answer
Python runs the checks from top to bottom and stops at the first one that is true.
If `int(text)` ran first on empty text (or on text like `"abc"`), it would crash with a `ValueError`, because that text is not a number.
So the safe checks (empty, then digits) must come first, and the number check comes last.
In the exam, the question tells you the order of the checks, and the sample output depends on it, so follow it exactly.

## 📝 Key points

- Comparisons (`==`, `!=`, `<`, `>`, `<=`, `>=`) give `True` or `False`.
- `=` stores a value. `==` asks a question.
- `if condition:` then an indented block. Use `elif` and `else` for other cases.
- In an `if` / `elif` chain, only the **first** true branch runs, so order matters.
- `and` needs both, `or` needs one, `not` flips. Use brackets when mixing `and` and `or`.
- For case insensitive checks, compare `a.lower() == b.lower()`.
- Clean typed text with `.strip()` before checking it.
- "Results in more than the maximum" means `count + 1 > MAX`.

## ⚠️ Common mistakes

| Mistake | What happens |
| --- | --- |
| `if x = 5:` | `SyntaxError` (use `==`) |
| Missing `:` after `if`, `elif` or `else` | `SyntaxError` |
| Wrong indentation under `if` | `IndentationError`, or a line runs when it should not |
| `day == "Sat" or "Sun"` | Always counts as true. Write `day == "Sat" or day == "Sun"` |
| `"Amy" == "amy"` | `False`. Use `.lower()` on both sides |
| `if count > MAX:` when the rule is about adding one more | Allows one item too many. Use `count + 1 > MAX` |
| Most general check first in an `elif` chain | The specific case is never reached |
