**What you will learn**

- What a function is, and why we use them.
- How to **define** a function and how to **call** it.
- How to give a function values to work with (**parameters**).

## 1. What is a function?

Think of a **vending machine**.

- You put something **in** (money and a button number).
- The machine does some work inside. You do not see how.
- Something comes **out** (a drink).

A function is the same:

- You give it some values (the **inputs**).
- It runs some lines of code.
- It can give you back a result (the **output**).

You already know some functions that Python gives you: `print()`, `len()`, `int()`, `type()`.
Now you will learn to write your own.

@@ md
## 2. Defining and calling a function

Here is a very small function:

```python
def showMenu():
    print("Milk Tea   $4.80")
    print("Green Tea  $3.90")
```

Let us read it piece by piece:

- `def` means "I am **def**ining a new function".
- `showMenu` is the name we chose. Use camelCase, like variables.
- `()` the brackets hold the inputs. This function needs none, so they are empty.
- `:` the colon says "the body starts on the next line".
- The body is the lines **indented** under it (4 spaces). They belong to the function.

⚠️ **Defining a function does not run it.**
It only teaches Python a new word.
To run it, you **call** it by writing its name with brackets: `showMenu()`.

@@ code
def showMenu():
    print("Milk Tea   $4.80")
    print("Green Tea  $3.90")

print("Before the call")
showMenu()
print("After the call")

@@ md
You can call a function as many times as you like.
That is the point of a function: write it once, use it many times.

@@ code
showMenu()
showMenu()

@@ predict Defining is not running
@@ run
def sayHi():
    print("Hi!")

print("Start")
print("End")
@@ output
Start
End
@@ explain
The function `sayHi` is defined, but it is never **called**.
There is no `sayHi()` line, so `Hi!` is never printed.

@@ predict Calling twice
@@ run
def cheer():
    print("Go")
    print("team!")

cheer()
print("---")
cheer()
@@ output
Go
team!
---
Go
team!
@@ explain
Each call to `cheer()` runs both lines of its body.
The function is called twice, so the two lines appear twice.

## 3. Parameters: giving the function some input

Most functions need some information to do their job.
You put a name inside the brackets of the `def` line.
This name is a **parameter**: a variable that gets its value when the function is called.

@@ code
def greet(name):
    print(f"Hello, {name}!")

greet("Amy")
greet("Ben")

@@ md
When we call `greet("Amy")`:

1. Python jumps into the function.
2. The parameter `name` gets the value `"Amy"`.
3. The body runs, and prints `Hello, Amy!`.
4. Python comes back and carries on after the call.

Two words that are easy to mix up:

- **Parameter**: the name in the `def` line (`name`).
- **Argument**: the actual value you pass in when you call it (`"Amy"`).

@@ predict One parameter
@@ run
def shout(word):
    print(word + "!!!")

shout("Hello")
shout("Stop")
@@ output
Hello!!!
Stop!!!
@@ explain
The first call sets `word` to `"Hello"`, the second call sets it to `"Stop"`.
Each time, the body joins `"!!!"` to the end.

## 4. Several parameters

A function can have several parameters.
Separate them with commas.
When you call it, the arguments are matched **in the same order**.

@@ code
def showOrder(drink, cups):
    print(f"{cups} x {drink}")

showOrder("Milk Tea", 2)     # drink gets "Milk Tea", cups gets 2
showOrder("Coffee", 1)

@@ predict The order of arguments matters
@@ run
def describe(name, age):
    print(f"{name} is {age} years old")

describe("Ali", 20)
describe(20, "Ali")
@@ output
Ali is 20 years old
20 is Ali years old
@@ explain
Arguments are matched by **position**.
In the second call, the first value (`20`) goes into `name` and the second (`"Ali"`) goes into `age`.
Python does not know that this is silly. It just follows the order.

@@ md
**Keyword arguments.**
You can also say which parameter gets which value, by writing its name.
Then the order does not matter.
You will see this in the course slides, for example `Customer('Jack', id='2', amt=50)`.

@@ code
def describe(name, age):
    print(f"{name} is {age} years old")

describe(age=20, name="Ali")

## 5. `return`: giving a value back

So far our functions only **print**.
Printing shows something on the screen, but the rest of your program cannot use it.

Remember the vending machine.
Printing is like the machine showing a picture of a drink on its screen.
`return` is the machine **dropping the real drink** into your hand, so you can use it.

@@ code
def double(number):
    return number * 2

result = double(4)
print(result)
print(double(10) + 1)

@@ md
When Python reaches `return`:

1. It works out the value after `return`.
2. It leaves the function **immediately**.
3. The function call is replaced by that value.

So `double(4)` becomes `8`, and `result = double(4)` is the same as `result = 8`.

🎯 Most exam methods **return** a value, for example "returns the total fees" or "returns True if added".
If the question says "returns", you must use `return`, not `print`.

@@ predict Return gives a value back
@@ run
def addOne(x):
    return x + 1

a = addOne(5)
b = addOne(a)
print(a, b)
@@ output
6 7
@@ explain
`addOne(5)` returns `6`, so `a` is `6`.
Then `addOne(a)` is `addOne(6)`, which returns `7`.

@@ predict Print is not return
@@ run
def addOneAndPrint(x):
    print(x + 1)

value = addOneAndPrint(5)
print(value)
@@ output
6
None
@@ explain
The function **prints** `6`, but it has no `return`.
A function without `return` gives back `None` (nothing).
So `value` is `None`, and `print(value)` shows `None`.
This is the most common function mistake. Learn to spot it.

@@ predict Printing the call
@@ run
def greetBack(name):
    print("Hi " + name)

print(greetBack("Sam"))
@@ output
Hi Sam
None
@@ explain
First Python runs `greetBack("Sam")`, which prints `Hi Sam`.
The function returns `None`, so the outer `print(...)` prints `None`.

@@ predict Return stops the function
@@ run
def getPrice():
    print("Looking up price")
    return 4.5
    print("This line is never reached")

p = getPrice()
print(p)
@@ output
Looking up price
4.5
@@ explain
`return` leaves the function straight away.
The line after `return` can never run.

@@ predict A returned value that nobody keeps

@@ explain

## 6. Using returned values

Because `return` gives back a real value, you can use the call anywhere you could use a value:
in maths, in an f-string, or as the argument of another function.

@@ code
def priceOf(cups):
    return cups * 4.80

total = priceOf(2) + priceOf(3)
print(f"Total: ${total:.2f}")
print(f"One cup: ${priceOf(1):.2f}")

@@ predict Calls inside maths
@@ run
def half(x):
    return x / 2

print(half(10) + half(4))
print(half(half(8)))
@@ output
7.0
2.0
@@ explain
`half(10)` is `5.0` and `half(4)` is `2.0`, so the sum is `7.0`.
In `half(half(8))`, the inner call runs first: `half(8)` is `4.0`, then `half(4.0)` is `2.0`.

## 7. A function can call another function

Big jobs are made of small jobs.
A function can call another function that you wrote before.

@@ code
def area(length, width):
    return length * width

def carpetCost(length, width, pricePerSqm):
    return area(length, width) * pricePerSqm

print(carpetCost(3, 4, 10))

@@ md
`carpetCost` does not repeat the area calculation.
It asks `area` to do it.
This is exactly how methods in a class will use each other, for example a `topUp` method calling `addBonus`.

@@ predict Following the calls
@@ run
def addTax(price):
    return price + 1

def finalPrice(price):
    return addTax(price) * 2

print(finalPrice(4))
@@ output
10
@@ explain
`finalPrice(4)` calls `addTax(4)`, which returns `5`.
Then `5 * 2` is `10`.

## 8. Default values for parameters

You can give a parameter a **default value** with `=` in the `def` line.
If the caller leaves that argument out, the default is used.

@@ code
def topUp(balance, amount=10):
    return balance + amount

print(topUp(5))        # amount is not given, so it is 10
print(topUp(5, 50))    # amount is given, so it is 50

@@ md
⚠️ Parameters with defaults must come **after** the ones without defaults.
`def topUp(amount=10, balance):` is a `SyntaxError`.

🎯 **Why this matters for the exam.**
Some languages let you write two functions with the same name but different parameters.
This is called **overloading**.
Python does not allow that, so we use default values instead.
The course slides do this with `def deduct(self, amount=5):`.
The exam has asked you to fix "overloading" code using default values.

@@ predict Default values
@@ run
def makeDrink(size="Regular", sugar=50):
    return f"{size} drink, {sugar}% sugar"

print(makeDrink())
print(makeDrink("Large"))
print(makeDrink("Small", 0))
print(makeDrink(sugar=25))
@@ output
Regular drink, 50% sugar
Large drink, 50% sugar
Small drink, 0% sugar
Regular drink, 25% sugar
@@ explain
With no arguments, both defaults are used.
With one argument, it goes into the first parameter, `size`.
With `sugar=25`, only `sugar` is given, so `size` keeps its default.

## 9. Variables inside a function stay inside

A variable created inside a function is **local**.
It only exists while the function is running.
Outside the function, Python has never heard of it.

@@ predict A local variable
@@ run raises=NameError
def makeSum(a, b):
    insideOnly = a + b
    return insideOnly

print(makeSum(2, 3))
print(insideOnly)
@@ output
5
@@ explain
`makeSum(2, 3)` returns `5`, which is printed.
But `insideOnly` was created **inside** the function.
Outside the function it does not exist, so `print(insideOnly)` fails with a `NameError`.
If you need the value outside, use what the function **returns**.

@@ predict Same name, different variable
@@ run
fee = 100

def addFee(amount):
    fee = amount + 5
    return fee

print(addFee(10))
print(fee)
@@ output
15
100
@@ explain
The `fee` inside the function is a **different** local variable that happens to have the same name.
Changing it does not change the `fee` outside, which is still `100`.

## 10. Common mistakes and their error messages

**Forgetting the brackets when you call.**
Without `()`, the function is not called.
Python just shows that the name is a function.

@@ code
def getMessage():
    return "Hello"

print(getMessage)      # no brackets: prints something like <function getMessage at 0x...>
print(getMessage())    # with brackets: calls it and prints Hello

@@ md
**Giving the wrong number of arguments.**
Read the message: it tells you which argument is missing.

@@ code raises=TypeError
def greet(name):
    print(f"Hello, {name}!")

greet()

@@ md
`TypeError: greet() missing 1 required positional argument: 'name'`

**Forgetting the colon** at the end of the `def` line.

@@ code raises=SyntaxError
def greet(name)
    print(f"Hello, {name}!")

@@ md
**Forgetting to indent** the body.

@@ code raises=IndentationError
def greet(name):
print(f"Hello, {name}!")

@@ md
**Calling a function before it is defined.**
Python reads from top to bottom, so the `def` must run first.

@@ code raises=NameError
showTotal(5)

def showTotal(amount):
    print(amount)

@@ predict Too many arguments
@@ run raises=TypeError
def area(length, width):
    return length * width

print(area(2, 3))
print(area(2, 3, 4))
@@ output
6
@@ explain
The first call has two arguments and works.
The second call gives three values, but `area` only has two parameters.
Python stops with `TypeError: area() takes 2 positional arguments but 3 were given`.

@@ write Return or print?
Explain the difference between `return` and `print` in a function.
Say what you get if you store the result of a function that only prints.
@@ answer
`print` only shows a value on the screen.
The rest of the program cannot use it.
`return` gives the value back to the line that called the function, so it can be stored, used in maths, or passed to another function.
A function that only prints (and has no `return`) gives back `None`.
So `x = functionThatOnlyPrints()` makes `x` equal to `None`.

## 📝 Key points

- `def name(parameters):` defines a function. The body is indented.
- Defining does not run it. Call it with brackets: `name(arguments)`.
- Arguments are matched to parameters by position, or by name (`amount=50`).
- `return` gives a value back and leaves the function at once.
- A function with no `return` gives back `None`.
- Default values: `def deduct(balance, amount=5):`. This is how Python does "overloading".
- Variables made inside a function do not exist outside it.

## ⚠️ Common mistakes

| Mistake | What happens |
| --- | --- |
| `print(...)` when the question says "returns" | The caller gets `None` |
| `getMessage` instead of `getMessage()` | The function is not called |
| Wrong number of arguments | `TypeError: ... missing 1 required positional argument` |
| No `:` at the end of the `def` line | `SyntaxError` |
| Body not indented | `IndentationError` |
| Using a local variable outside the function | `NameError` |
| Calling before the `def` has run | `NameError` |
